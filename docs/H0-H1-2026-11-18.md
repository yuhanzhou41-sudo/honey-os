## 本地改动

- C1.3 动态分段保留八条及更多自然聊天气泡，保留标点、结构化回复与历史分隔符。
- 回复前 Qwen 评估改为单次调用，套接字超时设为 20 秒。服务未配置、忙碌、离线或超时会沿用已有状态。收到中断后会丢弃评估结果。同步 HTTP 请求在网络调用返回前仍会占用调用线程。
- `honeyos.events.internal` 将会话库活动消息、Study 任务和调度器固定提醒转换为结构化事件。独立 SQLite 台账仅记录来源标识、类型、发生与摄入时间。
- `EventLedger` 以来源标识、事件类别和发生时间生成稳定 ID。来源撤回后，既有记录保留用于追溯，读取入口过滤该来源，重复摄入无法恢复它。
- 授权精确绑定主体、应用、来源和访问模式。当前可用能力为读取事件元数据。每次读取在同一事务中检查有效期和撤销状态，并记录通过或拒绝。调用方必须从可信环境提供主体并限制数据库文件访问。

- Node 22 加载 C1.3 TypeScript 源码并通过 5 项断言，覆盖八段历史和实时回复、段落、URL 及未完成流式片段。完整前端安装被 Windows 的 pnpm 符号链接权限错误阻止，构建与 Vitest 待复验。

## 恢复与后续验收

已经从独立源码副本读取并核实 `fde3827`。如需放弃实验改动，可从该提交新建本地分支。H1 台账仍为显式构造的独立文件，当前应用启动没有迁移或创建该库。

运行数据恢复应以选定版本的发布目录和配置为第一层，SQLite 一致副本及附件为第二层，关机状态的 WSL 虚拟磁盘为第三层。先核对快照时间、备份清单、凭证位置和目标盘容量，再将授权的数据恢复到与正式配置分开的目录。按现有开发进度记录核查回滚配置与各数据库快照，对副本运行 SQLite 完整性检查，再分别验证聊天、记忆来源和 Study 读写。

下一轮实机验收需要活动 WSL 或隔离运行环境，复测构建、当前静态资产、真实本地 Qwen 的冷/热延迟与连接失败、主模型 CLI、会话模型锁、自动分流和断线重试。H1 后续需接入 Gateway 身份验证和用户授权界面，明确来源撤回向各调用方传播的入口，再进入 Skill Registry 和 H3.1。
