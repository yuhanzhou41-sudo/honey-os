# Campus Hub 架构草案

## 当前链路

Study 的 `StudyCampusPanel` 通过客户端调用 `POST /api/study/campus/calendar`。Gateway 复用事件控制鉴权和 JSON 请求处理，将阻塞式读取交给后台线程，并以 `Cache-Control: no-store` 返回按日分组的数据。当前日期窗口最多 42 天。已确认无课以空列表表示，缺失日期表示未确认。需要登录返回 409 和 `login_required`，读取或参数失败返回 422。

Python CQMU 适配器调用 Node 脚本，在专用本机 Edge 中读取受限课表数据。Honey 的工作工具复用这条读取链路，但通过 `read_cqmu_timetable` 返回节次占用视图。现有共用边界位于来源适配器，统一能力目录、权限策略与审计仍待建立。

## 增量迁移

1. **C1 会话边界**。将独立 Edge Profile 和交互登录作为首选现有链路，提取会话状态与生命周期管理。保留现有 Study 路由请求、错误和数据语义。站点及跨域跳转须在验证后登记。
2. **C2–C3 发现与同步**。每个子系统由独立连接器输出允许的能力、覆盖状态和结构化记录。按来源、模块和外部键或指纹去重，保留来源定位、提取方式、观测及最近核验时间。同步失败保留旧记录并标记过期。原始页面默认不落盘。
3. **C4–C7 统一网关**。在现有 Gateway 内增量注册 `/api/campus/*`。Study 兼容入口、校园 UI 和 Honey 工具共享服务和授权。经验证的操作才进入能力目录，写操作经过 prepare → approve → execute → verify。原站禁嵌时由用户在独立窗口使用。
4. **C8–C9 调度与扩展**。复用调度基础设施做只读同步、退避及恢复。新模块适配器先隔离测试再审核启用。涉及 Study 计划、提醒或记忆的写入须分别授权。

校园记录与会话分开保存。后续使用独立 Campus SQLite 库，复用 Study 已有的连接、事务和版本化实践。新增迁移需验证初始化、升级、备份和恢复。认证数据由独立 Profile 管理。C0 没有数据库变更。
