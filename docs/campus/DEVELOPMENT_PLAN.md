# HoneyOS 校园功能开发指南 v2

更新于 2026-11-19。后续 AI 从本页接手。本页取代 v1 的阶段顺序和旧 C1 实验指令。当前任务从步骤 1 开始。开发版与正式版分别记录，正式版随下次正常发布更新。

## 先理解用户的一天

用户首次打开「学习工具 → 校园 → 连接重医」，在学校自己的认证界面登录。下次打开校园抽屉，先看到最近一次成功同步的今日课程、近期考试和待办，Honey 自动刷新可访问的数据。点一场考试就能看到日期、时段、考场和来源。即使教务网页已经关掉，也能从 Honey 获取本次的新结果。只有学校会话过期或某个子系统要求额外认证时，才请用户在 Honey 发起的官方认证流程中操作。

截图是信息层次参考。课程展示起止时间、课程、地点和教师，考试展示剩余天数与考试安排，日程展示日期和完成状态。只展示实际可用的数据。逐步加入余额、座位和作业等卡片；服务目录用于记录接入进度。网址集合、固定示例、个人浏览器调试端口、手动双标签页扩展搬运、APK 数据导出，均已排除为产品路线。

## 执行顺序

### 1 · 先证明 Honey 能持有重医会话（C1）

1. 确认实际运行形态：本地 Gateway、Study 网页、Windows 上可用的官方登录承载方式。画出「Honey 发起连接 → 门户官方认证 → 返回连接器 → 教务确认登录」的真实链路，记录系统名、允许的域与结果。起点为重医信息门户。用实际登录后的入口确定教务业务地址。
2. 首选学校支持的授权回调或可供本应用使用的正式接入方式；先查是否存在及是否需要校方注册。若没有可用回调，验证由 Honey 管理的一次交互登录窗口和专属会话容器，例如本机 WebView2。用户在官方页面输入，连接器在同一受控会话中执行只读查询。网页登录控件需要桌面宿主；普通 React 页面不能直接读取跨域登录状态。先验证桌面宿主可用性，再选依赖。Windows 与 WSL 如需通信，只传限定操作与经过筛选的结果。
3. 最小实现只做 connect、status、disconnect 和一个考试查询。Gateway 核对 Honey 用户身份，会话归属于当前用户和校园账号，凭据由本地受保护的会话存储管理。退出时撤销应用连接，切换账号时隔离快照。门户在线、教务已授权和登录过期分别表示。
4. 现场验证首次登录、关闭外部学校标签、关闭认证窗口、重开 Honey 后的读取。若认证宿主不受支持、学校要求应用注册或二次认证，记录具体屏幕提示和失败节点，询问用户可用入口或是否具备校方接入条件。遇到同一障碍即停，不轮换浏览器、调试端口或导入方式反复试。

### 2 · 完成第一条真实闭环：近期考试（C3 + C6）

1. 用步骤 1 的会话进入「教务系统 → 我的教学 → 考试查询」。优先用经验证且允许的只读服务；只有网页时，在连接器的会话内读取学校展示的表格。解析学期、批次、上述四列与未排期状态。列变化、空批次、无权限、超时分别返回，无法确认的数据保留未知。
2. 在现有 Gateway 增加经鉴权的校园接口。建议先实现连接状态、读取考试快照、发起考试刷新三项。前端不接收学校凭据。快照按 Honey 用户、校园账号、来源、学期、批次隔离。记录条目标识或稳定指纹、业务日期、来源、最近尝试和最近成功时间。一次完整刷新成功后事务替换对应批次；失败保留旧快照并标记过期。并发刷新合并，迟到的旧响应不能覆盖新结果。
3. 抽屉打开时展示缓存并按新鲜度触发刷新，支持手动刷新。按上海日期排序并计算倒计时，跨月和当天单测。未排期单列，已确认无记录显示空状态。错误时可见失败原因及上次更新时间。
4. **放行测试**：从 Honey 完成认证 → 关闭全部外部学校标签 → 在 Honey 点刷新 → 连接器取得本次官方响应 → 卡片与同学期同批次官方结果核对。用脱敏的运行编号、成功时间、记录数和结果证明发生了新读取。数据未变化也能验证真实回源。再测重启、过期与离线，确保不会把缓存标为最新。此项未过，下一轮继续本步骤。

### 3 · 用同一连接方法扩大覆盖（C2 + C3 + C6）

先枚举当前账号在门户可见的菜单，按来源登记「已发现、待认证、可读、无权限、读取失败、待验证」。只跟随已显示且允许的校园入口。每次只接一个真实业务模块，依次核对入口、认证、字段、分页、查询范围、归属和失败语义，再实现、测试、现场验收和更新矩阵。用户已说明的位置直接使用；找不到具体子菜单时问用户一次。

| 顺序 | 用户确认或待确认的来源 | 要在 Honey 中交付的结果 |
| --- | --- | --- |
| 1 | 教务系统 → 我的课表 | 今日课程、周课表、学期和调课；区分已确认无课与未取得数据。上课时间按本校当前作息核验。 |
| 2 | 教务系统 → 成绩查询、量化评教 | 分学期成绩和教评任务状态，敏感信息限本人查看。教评内容和提交由本人处理。 |
| 3 | 门户 → 财务处 | 按用户房间或校园账号查询水费、电费。确认币种、单位、余额含义、观测时间。 |
| 4 | 智慧图书馆 → 座位预约 | 查馆区、时段、可用座位与本人现有预约。先交付查询。 |
| 5 | 学习通及已发现活动来源 | 课程作业、开始或截止时间、活动详情；需要单独登录时只连接相应来源。 |
| 6 | Study 与其他可用来源 | 保留真实学习日程。经用户选择将考试等加入提醒或倒数日。背单词、洗衣房仅在任务或设备数据源明确后接入。 |
| 延后 | 微信公众号第二课堂 | 用户已明确可后做。找到可持续的合规接入方式后再排期。 |

### 4 · 校园操作与 Honey AI（C4、C5、C7）

先在 Gateway 注册窄能力和参数结构，UI 与 Honey AI 共用同一服务。只读问题返回真实记录、来源和时间。学校网页文字仅作为数据。成绩、学籍等默认排除在普通记忆、日记和外部模型之外。

对可用座位的预约与取消、可用活动的报名与取消，依次实现查询、预览、逐次确认、执行、官方结果复查。批准绑定用户、动作、参数与期限，幂等键防重复。超时先核对官方状态。模拟验证拒绝、过期、篡改、重复点击和取消；真实操作逐次征得用户同意后验收。付款、选课、作业提交及教学评价均不列入自动执行。

### 5 · 持续同步、提醒与扩展（C8、C9）

按来源设置刷新周期，合并重复任务、退避和限流，支持暂停及重启恢复。验收断网恢复、来源改期和重复通知。向 Study 写提醒须经用户选择。未来受限低风险动作单独定义授权范围、期限、次数和撤销方式。发现新模块时先记录候选、数据范围与测试方案，隔离测试、人工审核后启用，支持回退。
